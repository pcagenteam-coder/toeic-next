# TOEIC 合并项目 · 算法 Track 方案

> 定位：只做方案，不建仓库、不写完整引擎代码。
> 决策基线：以 toeic-reading 引擎为“脑子”，以 Sesame 引擎为补充；
> 两者都只做阅读 Part 5 / 6 / 7，不做听力。
> 许可红线：本方案只定义字段与规则，不搬运、不公开任何无许可题库内容。

## 1. 统一引擎接口

> 2026-11-03 用户确认冻结补正：引擎输出的掌握度与预测分变化默认就推到界面（3 秒回报闭环），“考生视角”只切换展示字段的细节层，不切换算法，也不决定是否显示对错与预测分变化。下文凡与本条冲突的“默认不暴露分数”表述，一律以本条为准。

引擎必须是纯函数核心，与界面、存储、网络解耦。同一份状态输入，
同一份选题/更新规则，在单文件离线版、云同步版、测试里结果一致。

```text
EngineState -> select(session) -> SessionPlan
EngineState + AnswerEvent -> EngineState' + Feedback
EngineState -> predict() -> Prediction
EngineState -> reviewDue(date) -> Card[]
EngineState -> exportProgressCode() -> string
importProgressCode(string) -> EngineState   # 永远新建档案，不覆盖原档案
```

### 1.1 核心不变量

- 只支持现行新制：Reading 75 分钟 100 题，P5 30 / P6 16 / P7 54。
- 旧制题型、旧制技巧一律标 `deprecated`，不进图谱、不进选题池。
- 模考一旦交卷，该套记入 `used`，此后不再进训练池（见 3.5）。
- 用户每场只做一个选择：5 / 20 / 75 分钟；其余由引擎决定。
- 答题时默认暴露对错、用时、掌握度变化与预测分变化；内部难度参数、FSRS 原始间隔、引擎权重不暴露。考生视角只展开区间与细节。
- 所有动作写日志，日志可导出，但进度码不含日志（控制体积）。

### 1.2 数据模型

#### 能力与节点（Ability / Node）

```text
EngineState {
  user: { name, targetTotal: 600|700|800|900, examDate? }
  theta: number              # 全局能力，logit 尺度
  answeredCount: number      # N，用于学习率衰减与区间收窄
  nodes: Map<nodeId, NodeState>
  cards: Map<cardId, CardState>
  usedForms: string[]        # 已用模考套
  doneItemIds: Set<string>   # 已做题，用于未做优先与防重复
  log: LogEvent[]            # 上限 20000 条，超限滚动丢弃最旧
}

NodeState {
  id: string                 # 图谱节点 id，305 节点体系内唯一
  theta: number              # 节点能力，首次触达用当前全局 theta 初始化
  n: number                  # 该节点作答次数
  examWeight: number         # 考频权重，来自考频统计
  mastery: number            # = sigmoid(theta)，展示用，不单独存储为事实
  lastSeenAt: string         # ISO 日期，用于遗忘衰减
  confidence: number         # 0-1，样本越少越低；未测节点不等于 0%
  status: "unmeasured" | "measured"
}
```

要点（两项目合并后的统一口径）：

- 节点首次触达用当前全局能力初始化，禁止默认 0 或默认 50%。
- 未测不等于不会：展示为“未测”，预测与推荐里用全局能力打折（见 2.1），
  不把未测当成掌握度 0。
- 主节点与关联节点更新强度不同：主节点用全量 K，关联节点用 K/2。
- 节点分层：6 层折叠展示，叶子节点显示掌握度条或“未测”，
  分组节点只做小标题，不直接参与单题更新。

#### 题目（Item）

```text
Item {
  id: string
  part: 5 | 6 | 7
  bundleId?: string          # P6 / P7 按 bundle 出题，P5 为空
  qnum: number
  qtype: string              # 67 个 qtype 叶子之一
  nodeIds: string[]          # 主节点在首位，其余为关联节点
  difficultyEst: 1..5        # 难度估计，difficulty v2 后的值优先
  targetTimeSec: number
  options: string[4]
  answer: 0..3
  explainZh?: string
  whyZh?: string[]           # 每干扰项错因，缺失时展示为“暂无错因”，不编造
  source: string
  licenseTier: "public" | "gated" | "private"   # 见题库 track，不在本文件展开
  flags: string[]            # passage_missing / unverified / deprecated 等
  form?: string              # 模考套归属，训练选题时用于 used 隔离
}
```

难度换算（沿用 toeic-reading 口径，统一后不再各自定义）：

```text
b = (difficultyEst - 3) * 0.7        # logit 尺度难度
pCorrect = sigmoid(theta - b)
```

#### 卡片（Card，FSRS 对象）

一张卡可以是一道题、一个考点、一条技巧或一个生词，统一用同一套
间隔规则调度，区别只在内容载体。

```text
CardState {
  id: string                 # 题卡 / 考点卡 / 词卡，id 前缀区分类型
  kind: "item" | "node" | "skill" | "word"
  refId: string
  dueDate: string            # ISO 日期
  intervalDays: number
  state: "new" | "learning" | "review"
  lastOutcome: "fast_correct" | "slow_correct" | "wrong" | "lookup"
}
```

#### 日志与进度码（Log / ProgressCode）

```text
LogEvent {
  ts: string
  kind: "answer" | "lookup" | "defer" | "highlight" | "review" | "mock" | "import"
  itemId?: string
  nodeIds?: string[]
  correct?: boolean
  usedSec: number
  targetSec?: number
}

ProgressCode = base64(UTF-8 JSON {
  app: "toeic-merged-v1",
  name: string,
  st: EngineState   # 不含 log
})
```

- 进度码导入永远新建档案，不覆盖；导入失败要明确报错，不静默丢数据。
- 存储优先 localStorage，写读先做容量测试；失败或配额满时走内存运行，
  并在顶部提示用户复制进度码；云同步只做 get / set / del 同接口的适配层，
  不改变引擎状态结构。

## 2. 统一更新规则

### 2.1 Elo 式掌握度更新（toeic-reading 为主，Sesame 为补充）

单题作答后，按以下顺序更新，禁止只更新全局、不更新节点，
或只更新节点、不更新全局：

```text
r = 1 if correct else 0
p = sigmoid(theta - b)

# 全局能力，学习率随作答数衰减，下限保底
Kg = max(0.06, 0.6 / (1 + 0.05 * N))
theta += Kg * (r - p)

# 节点能力
主节点 K = max(0.15, 0.8 / (1 + 0.1 * n))
关联节点 K = K / 2
对每个 nodeId：
  pNode = sigmoid(node.theta - b)
  node.theta += K * (r - pNode)
  node.n += 1
  node.lastSeenAt = today
```

Sesame 补充项，合并后必须同时满足：

- 证据权重：首次作答权重 1，重复作答权重 0.3，模考作答权重 1.2；
  慢对（用时超过目标）证据权重再乘 0.7。
- 成功率目标带：选题与推荐应把期望正确率维持在 70-85%，
  过易或过难的题即使薄弱也不优先推。
- 置信度：样本少时展示区间、不展示虚假精确分；未测节点置信度最低，
  但不等于掌握度 0。

### 2.2 遗忘衰减（Sesame 补充，toeic-reading 原来缺这一块）

- 衰减只发生在“读取 / 推荐 / 预测”时按 `lastSeenAt` 计算，
  不在每次作答时静默改写历史；衰减结果要可复现、可测试。
- 推荐口径：有效掌握度 = 原始掌握度向全局能力收缩，
  时间越久、样本越少，收缩越强；禁止衰减后直接把掌握度清零。
- 衰减不改变卡片的到期日本身；卡片到期仍由 FSRS（第 4 节）决定。
  两者分工：衰减影响“推荐优先级与预测”，FSRS 决定“今天复习什么”。

### 2.3 薄弱点与优先级（两项目统一公式）

```text
薄弱点得分 = examWeight * (1 - mastery)
Sesame 优先级 = 权重 * 缺口 * 斜率 / 用时
```

合并后使用方式：

- 薄弱榜排序用 `examWeight * (1 - mastery)`，取前 15。
- 单题 / 单组推荐排序用 Sesame 优先级做二次排序：
  权重取考频，缺口取 (1 - mastery)，斜率取该节点近 7 天掌握度变化，
  用时取该题目标用时；斜率缺失时按 1 处理，不直接排最后。
- 未测节点：用全局能力估计掌握度，再乘 0.9，避免未测节点永远排不到前面，
  也不让未测节点无条件置顶。

## 3. 五种模式的选题与更新规则

### 3.1 诊断（入职测评，约 12-13 题）

选题：

- P5 难度 2、2、3、3、4、4 各 1 题，共 6 题。
- P6 一篇（4 题）+ P7 单篇一组（不超过 3 题）。
- 全部用未做过的 pilot / 原创题，不用模考套，不用私有无许可题做首测。

更新与反馈：

- 答完直接下一题，全程不给反馈、不给规则卡、不给分数。
- 每题仍正常更新全局与节点能力（诊断不是只测不学）。
- 最后一次性出结果：预测分区间、薄弱点前几名、下一步建议；
  不出逐题解析榜，避免首测变成讲题课。

验收：新用户 12-13 题内完成；诊断后预测区间半宽符合第 5 节公式；
诊断题不进入后续模考套的“已用”判定，只记入 `doneItemIds`。

### 3.2 训练（5 / 20 分钟，日常主模式）

选题（沿用 toeic-reading 结构，加入 Sesame 成功率带约束）：

- 5 分钟：到期复习卡不超过 4 道 + P5 薄弱题补到 8 道。
  薄弱节点里 P5 不够时，用其余 P5 补足，不降级去推 P6 / P7 凑数。
- 20 分钟：复习卡不超过 10 道 + P5 8 道 + P6 1 篇 + P7 单篇 1 组，
  全部偏向前 6 薄弱节点。
- 单题排序：未做优先，其次 |b - theta| 小优先（即期望正确率靠近
  70-85% 带），再加小随机扰动，避免同一用户永远同一顺序。
- 练习工具可用：稍后处理（单题移到末尾 / bundle 内移到本组末尾）、
  划依据（按 bundle 记录）、点词进生词本（本题记为“查词”，见 3.3）。

更新与反馈：

- 答后给一句职场反馈、正确答案、用时 vs 目标、中文解析、考点名；
  干扰项错因只有有数据的题才展示，缺失不编造。
- 同主节点连错 2 次及以上，才出现“看工作规则卡”按钮，
  规则卡取技巧库中绑定该节点或其父节点、且 `practice_mode = true` 的前 2 条。
- 训练不设单场结算屏；一天只做一次日结算（见 3.3 末尾）。

### 3.3 复习（跟进 / 错题 / 生词，FSRS 驱动）

选题：

- 到期卡优先，复习页一次最多 20 张。
- 每日复习上限约一半：5 分钟卡最多 4 道复习，20 分钟卡最多 10 道复习，
  剩余名额留给新薄弱题；禁止复习把整场占满。
- 错题本支持重做，生词本支持删除；重做结果重新走 FSRS，不直接覆盖旧卡。

更新（简化 FSRS，见第 4 节）：

- 快对（用时 <= 目标）：间隔 × 2.5。
- 慢对：间隔 × 1.3。
- 错，或本题查过词：间隔回到 1 天。
- 新题快对且没查词：不建卡（已会，不浪费复习名额）；其余都建卡，
  错题进错题本。
- 生词：认识 × 2.5，模糊 × 1.3，不认识 → 1 天。

日结算（一天一次，不按场结算）：

- 题数、正确率、用时 vs 目标总和、预测分变化、涉及主节点涨跌各前 4、
  职级变化（变化时提示晋升）。
- 职级映射（沿用 toeic-reading）：<200 实习生，200 专员，300 主管，
  375 经理，430 总监；职级只展示，不参与选题。

### 3.4 攻克（单节点专项）

选题：

- 该节点 P5 6 道 + 含该节点的 P6 / P7 各 1 组（题库有才出，没有不硬凑）。
- 攻克题同样遵守成功率带与未做优先；攻克不是无限刷同一节点，
  同一节点连续攻克超过 2 场要提示换节点或进混合训练。

更新与反馈：

- 与训练相同，但结算要单独标注“攻克节点掌握度变化”，
  便于用户判断该节点是否真的补上，而不是只看总分。
- 攻克完成后，该节点卡片按 FSRS 重新排期，不立即再次推送。

### 3.5 模考（75 分钟整套，验证模式）

选题：

- 整套定义：题数 >= 90 的 form，不写死来源；公开构建用开源整套，
  私有构建另有整套；以后新增整套自动生效，不改引擎代码。
- 选未用过、且已练过题最少的整套；pilot 迷你卷不够数，不进模考。
- 75 分钟倒计时为绝对截止，暂停不停表；无工具、无反馈；
  支持上一题 / 下一题、题号导航（已答着色）、交卷确认；时间到自动交卷。
- 交卷后统一记分（未答按错），该套记入 `used`，此后不进训练池。

更新与报告：

- 模考作答权重 1.2，按 2.1 更新全局与节点能力。
- 报告：换算分、各 Part 对题数、结算项；同时记录该套与预测分的偏差，
  作为第 5 节校准的输入样本。
- 模考报告不直接改写日常预测分的换算表；换算表变更只走校准流程。

## 4. FSRS 与遗忘衰减的合并方式

两者分工必须写进代码注释与测试，不允许混成一个“间隔”概念：

| 机制 | 决定什么 | 输入 | 输出 |
| --- | --- | --- | --- |
| 简化 FSRS | 今天复习什么、下一张卡何时到期 | 上次结果、快 / 慢对、是否查词 | 到期日、间隔天数 |
| 遗忘衰减 | 推荐优先级、预测分、薄弱榜 | lastSeenAt、样本数、全局能力 | 有效掌握度、置信度 |

合并规则：

1. FSRS 先算到期日；到期卡进入复习候选池。
2. 衰减再算有效掌握度；有效掌握度用于薄弱榜与选题排序，
   不反向修改卡片到期日。
3. 考前压缩：临近考试日时，FSRS 间隔按考试日截断，
   到期项写进次日内容；禁止考前把所有卡一次性提前。
4. 每日复习上限约一半，见 3.3；上限是保护机制，不是目标值，
   复习池不足时不强行补新题凑满。
5. 慢对、查词、错题三类结果一律不延长间隔；快对才延长，
   且新题快对无查词不建卡。

## 5. 预测分校准计划

### 5.1 当前预测公式（合并后基线，不擅自改换算表）

```text
难度分布 b ∈ {-1.4, -0.7, 0, 0.7, 1.4}，权重 .1 / .25 / .35 / .2 / .1
期望正确率 = Σ 权重 * sigmoid(theta - b)
原始分 0-100 -> 分段线性换算表 SCALE -> 5-495，取 5 的倍数
区间半宽 = max(20, 150 / sqrt(1 + N / 8))，随作答收窄
阅读目标 = 总分目标 / 2（600 -> 300，900 -> 450）
达标概率 = Φ((预测 - 目标) / (半宽 / 1.645))，logistic 近似
```

### 5.2 校准流程（分三步，缺一步都不发布新换算表）

第一步：收集对照样本。

- 每场模考记录：预测分、区间、实际换算分、各 Part 对题数、
  模考套 id、作答数 N、是否首次做该套。
- 样本按 Part 与难度分层，不只看总分；P5 / P6 / P7 偏差方向不同时，
  不用一个总系数硬调。

第二步：验证换算表。

- 指标：平均绝对误差（MAE）、偏差（预测 - 实际均值）、
  区间覆盖率（实际分落在预测区间内的比例，目标约 90%）。
- 样本量门槛：少于 30 场模考不改换算表，只报告偏差；
  30 场以上才允许分段调整，且每次只调一个分段。
- 阅读 = 总分 / 2 只是近似，必须在报告里标注，不写成官方换算。

第三步：发布与回滚。

- 换算表变更走版本号：`SCALE v1 -> v2`，旧预测结果保留快照，
  新旧换算在同一批样本上并行跑一遍，MAE 变差则回滚。
- 预测分展示永远带区间，不只给单点分；区间半宽下限 20 分，
  不因样本多就收敛到虚假精确。

### 5.3 校准验收指标

- 模考对照 MAE 目标：从基线起，每轮校准后不恶化，最终 <= 25 分。
- 区间覆盖率：80-95% 之间；低于 80% 说明区间过窄，高于 95% 说明区间过宽。
- 分段偏差：任一 100 分段的平均偏差绝对值 <= 30 分，否则该分段单独复核。
- 模考套泄漏检查：校准样本里不得含有训练池已练过的整套题，
  一旦发现，该样本作废并修复 used 隔离逻辑。

## 6. 已知坑修复清单与验收指标

### 6.1 图谱 305 行渲染慢

- 现状：图谱 Tab 一次渲染 305 行，低端机可能慢。
- 修复：按 6 层折叠，默认只渲染分组标题与已展开分组；
  叶子节点虚拟滚动或分页渲染；掌握度条用 CSS 宽度，不用逐行重算。
- 验收：图谱首屏渲染 < 500ms（中端手机，Chrome 性能面板抽查）；
  折叠 / 展开不触发全量重渲染。

### 6.2 模考题泄漏进训练池

- 现状：模考可能包含训练里做过的题；选“练过最少”的套只是缓解。
- 修复：`usedForms` 与 `doneItemIds` 双重隔离；选题时先排除
  `usedForms` 内所有题，再排除已做题（未做优先除外，见 3.2）；
  新增整套入库时自动跑泄漏检查，命中训练池的题要标出并隔离。
- 验收：新增整套泄漏检查 100% 跑通；随机抽查 100 场训练选题，
  0 场含有 `usedForms` 内的题。

### 6.3 点词不查义

- 现状：点词只收词不查义，无离线词典；本题记为“查词”但用户看不到释义。
- 修复：点词至少给 NGSL / TSL 词表内的释义与例句；超纲词先收进生词本，
  释义缺失时明确标“暂无离线释义”，不编造；后续再接离线词典，
  不阻塞第一版合并。
- 验收：词表内点词 100% 有释义；词表外点词 100% 标缺失，不出现空卡；
  点词后该题仍按“查词”走 FSRS（间隔回 1 天）。

### 6.4 预测分近似

- 现状：换算表、阅读 = 总分 / 2 都是近似，需模考校准；区间可能虚假精确。
- 修复：见第 5 节；展示层永远带区间与“约”字样；换算表变更走版本与回滚。
- 验收：见 5.3；未达样本量门槛时，界面明确标注“预测仅供参考，待模考校准”。

### 6.5 其他合并时必查坑

- 模考暂停不停表：暂停按钮只停界面计时显示，不停绝对截止；测试必须覆盖。
- 诊断反馈泄漏：诊断全程无反馈、无规则卡，测试覆盖诊断路径。
- 规则卡滥用：同主节点连错 < 2 次不弹规则卡；测试覆盖连错 1 次与 2 次两种情况。
- 进度码覆盖：导入永远新建档案；测试覆盖导入后原档案仍在。
- 本地存储满：localStorage 写失败时走内存运行并提示复制进度码；
  测试覆盖配额满分支，不静默丢进度。
- P6 / P7 bundle 拆散：P6 / P7 必须按 bundle 出题，不拆单题进 P5 池；
  攻克、复习、模考都要覆盖 bundle 完整性检查。

## 7. 与其他 Track 的接口约定

- UX track：引擎只输出 `SessionPlan`、`Feedback`、`Prediction`，
  不决定文案、颜色、动画；“考生视角”开关只切换展示字段的细节层，不切换算法，也不决定是否显示对错与预测分变化。
- 题库 track：引擎只认第 1.2 节的 Item schema；来源、许可、去重、
  难度重评由题库 track 负责，引擎不解析原始题源。
- 架构 track：引擎是纯函数核心，存储适配（localStorage / Supabase）
  与网络只在外层；引擎测试不需要浏览器、不需要网络。
