# 题库归并 Track 方案：TOEIC 合并新项目

> 定位：只做方案与可执行清单。
> 不建 GitHub 仓库，不把无许可题写进公开文件，不复制任何 API Key、密码或 token 到文件或输出。
> 本文件不含任何题目原文、选项原文或解析原文，只写字段、流程、规则和检查点。

## 0. 背景与红线

### 0.1 已核实的输入规模（不能直接相加）

- Sesame-toeic：清洗后主库 `merged_items_dedup_private.json` 7398 题；另有 Supabase `gated_content`（P5NEW、P7NEW），登录后才能读。
- toeic-reading：难度重评 v2 公开 1511 题、私有 4855 题；另有自编 pilot 107 题、MIT 开源 600 题、新东方 2019 1000 题（其中 30 题原文缺图）、ETS 转录等。
- 两边来源大量重叠（Sesame 的 `sources.lock.tsv` 已记录 toeic-reading 等上游），7398 与 6366 不能直接相加。真实 distinct 题数以去重报告为准，在此之前一律写“待去重报告确认”，不报合计。

### 0.2 许可三层防火墙（归并的第一原则）

许可层级一旦定下，只能降级，不能升级。去重时“保留哪一条”不改变被保留条目的许可层。

| 层 | 含义 | 可进哪里 | 绝对禁止 |
|---|---|---|---|
| A：可公开 | 自编题、MIT 开源题、NGSL 1.2 / TSL 1.2 词表、原创技巧库与解析 | 公开构建、公开仓库 | 混入 B/C 层原文 |
| B：登录可见 | Sesame 式 `gated_content`：登录后才能读的版权题（例如 P5NEW、P7NEW） | 登录后构建 / Supabase gated 表，构建时做泄漏检查 | 出现在公开网页、公开构建产物、公开仓库历史中 |
| C：仅自用 | ETS 转录、无许可第三方题、新东方等无授权题、B 站抓取等 | 私有仓库 + 私有 Release；仅内部校准、难度统计、去重比对 | 进入公开构建、公开仓库、公开解析、公开报告示例 |

构建时必须跑泄漏检查，思路沿用 Sesame 构建的做法：检查 B/C 层题干、原文、解析文字没有漏进公开网页，漏了就停，不发布。

### 0.3 归并总原则

1. 先出报告，再写库。任何批量改库动作之前，先有可审的报告。
2. 保留来源链（provenance）。每题都要能追溯到原始来源和原始 ID，删源不删链。
3. 模考与训练分池。整套模考题一旦划入模考池，就不再进训练池（见第 4 节）。
4. 模型只做建议，不直接定稿。DeepSeek 4.1 的批量输出一律先过自动审题 + 人工抽查，再写库（见第 5 节）。

## 1. 统一 Schema（以 toeic-reading pilot schema 为底）

所有来源先映射到同一张表，再谈去重。字段名保持英文，中文说明只写含义，不写题目内容。

### 1.1 题目本体字段（必填，除非注明可选）

| 字段 | 含义 / 规则 |
|---|---|
| `id` | 归并后全局唯一 ID。格式建议：`MERGED-<来源简码>-<原始ID>`；去重合并后保留主 ID，被合并 ID 写入 `merged_from`，不删除记录链 |
| `bundle` | P6/P7 的组 ID；P5 单题为空或单题组。同一 bundle 的题必须同进同出、同许可层 |
| `qnum` | 题号。P6/P7 在 bundle 内的序号；模考套题还需记录套内原始题号 |
| `part` | `P5` / `P6` / `P7`，只取现行新制 |
| `qtype` | 题型。P5 按语法/词汇细分；P6 含句子插入位置；P7 按设问族 × 文本类型 |
| `node_ids` | 能力图谱节点 ID 列表。主节点在前；节点必须存在于图谱中，不存在先补图谱或打 `node_missing` |
| `difficulty_est` | 难度估计。沿用 toeic-reading 的 1–5 档或 difficulty v2 的 score/band；未评的写 `null`，不猜默认值 |
| `target_time_sec` | 目标用时（秒）。P5/P6/P7 分 Part 给默认值表，单题可覆盖；缺失写 `null` |
| `explain_zh` | 中文解析。A 层可用原创/开源解析；B 层仅登录后可见；C 层不生成、不改写、不外发可公开解析（见第 5.4 节） |
| `why_zh` | 逐干扰项错因。结构为 `选项 -> 错因` 的映射；只有确实有错因的题才填，没有写 `null`，不编造 |
| `source` | 来源简码 + 来源名，例如自编 pilot、MIT 开源、XDF2019、ETS 转录、Sesame merged 等 |
| `license` | 许可层：`A` / `B` / `C`，以及原始许可备注（MIT / CC BY 4.0 / CC BY-SA 4.0 / 无许可仅自用等） |
| `flags` | 标志数组，见 1.3 节 |

### 1.2 来源与追溯字段（必填）

| 字段 | 含义 / 规则 |
|---|---|
| `source_id` | 原始来源内的原始题 ID |
| `source_commit` | 原始仓库 commit 或快照 tag；Sesame 的 `sources.lock.tsv` 思路直接复用 |
| `form` | 模考套名（如 MXT01、XDF T01 等）；非套题写 `null` |
| `passage_id` | 原文 ID；P5 单题可为空 |
| `merged_from` | 被合并进本题的其他原始 ID 列表；空数组表示未合并 |
| `provenance_note` | 来源链备注：例如“由 X 来源 Y 题合并，保留主 ID，原因见去重报告编号” |

### 1.3 flags 标志（多值，命中即打标，不直接删除）

- `passage_missing`：原文缺图 / 原文残缺
- `unverified`：答案或解析未经复核
- `deprecated`：旧制题型（例如旧制 P5 40 题制、改错题等），不进图谱
- `mock_only`：划入模考池，见第 4 节
- `node_missing`：节点不存在或粗打待复核
- `explain_missing`：无中文解析
- `why_missing`：无干扰项错因
- `near_duplicate_candidate`：近似去重候选，待人工裁决
- `license_conflict`：同一题目在不同来源许可不一致，默认取最严一层，并人工复核

## 2. 去重流程：两步，先精确后近似

### 2.1 去重前的归一化（两步共用，不做这一步不准比对）

1. 文本归一化：统一全半角、空白、标点、大小写；去掉题号、页眉页脚等排版噪声；数字、专有名词保留原样。
2. 选项归一化：选项顺序不参与精确比对，只参与近似比对时的“选项重排”识别；选项文字归一化后排序再哈希。
3. 原文归一化：P6/P7 以 bundle 原文为单位归一化；P5 以题干为单位。
4. 生成比对键：
   - 精确键 A：`hash(归一化原文 + 归一化题干)`（P7 多篇以全部原文拼接）
   - 精确键 B：`hash(归一化题干 + 排序后选项)`
   - 近似键：原文前 N 句 + 题干关键词 + 选项集合的指纹，用于候选召回，不直接定罪。

### 2.2 第一步：精确去重（自动执行，可写库，但要留报告）

- 命中规则：精确键 A 或精确键 B 完全相同，即判定为同一题。
- 处理动作：
  1. 按第 3 节保留优先级选一条为主记录。
  2. 其余记录不删除，写入主记录的 `merged_from`，并在去重报告中列出被合并 ID、来源、许可层。
  3. 许可层取并集中最严的一层；若主记录是 A 层、被合并记录是 C 层，合并后整题降为 C 层，绝不反向升级。
  4. 难度、解析、错因取“最完整且已复核”的那条，不自动拼接不同来源的解析。
- 输出：去重报告（报告-only 的部分，见第 5.1 节）+ 待写库的合并映射表。映射表经抽查后方可写库。

### 2.3 第二步：近似去重（只出候选，人工裁决后才写库）

近似去重不自动删题、不自动合并，只产出候选组供人工裁决。

- 召回候选的信号（任一命中即进候选，不单独定罪）：
  1. 原文高度相似但题干改写（同义改写、换主语、换数字以外的改写）。
  2. 题干相同、选项重排或个别选项同义替换。
  3. 同一 ETS / XDF 套题在不同来源被拆成不同 bundle 或不同题号。
  4. P7 多篇中单篇被单独抽出成单篇题。
- 裁决动作（人工或人工 + 模型辅助建议，模型建议不等于裁决）：
  1. 同一题：按第 3 节合并，处理同精确去重。
  2. 同源变体题：保留两题，但互相标注 `variant_of`，选题时避免同一 session 内同时出现。
  3. 不同题：标注 `reviewed_not_duplicate`，以后不再重复召回为同一组。
- 输出：近似去重候选报告，含每组的相似信号、建议、裁决栏（同一题 / 变体 / 不同题 / 待定）。未裁决的组不进写库队列。

### 2.4 去重范围与顺序

1. 先在同一许可层内去重（A 内、 B 内、 C 内），再跨层比对。
2. 跨层比对只做“识别重复”，不做“跨层合并成公开题”。跨层重复的结果是：公开层不因此获得无许可题的权利；内部统计时按最严层计数。
3. 先 P5，再 P6/P7 bundle 级，最后 bundle 内题级。bundle 级重复的，整组先裁决，题级不再单独拆开处理。

## 3. 保留优先级（主记录选择规则）

同一题多来源时，按以下顺序选主记录；前一条能区分就不再往下比。

1. ETS 官方样题（有明确来源的样题）
2. 自编 pilot 题（原创、已审题、字段最完整）
3. MIT / 其他明确开源许可题（例如 maximcuynat、lumi-open-data）
4. Sesame 已清洗合并题（以其清洗结果为准，但许可层仍按原始来源取最严）
5. 无许可转录题（XDF、ETS 转录、第三方抓取等）——仅 C 层内部可用，绝不因“字段更完整”而升级为 A/B

补充规则：

- 字段完整度、已复核状态、难度已评状态作为同级内的加分项，不跨越上面的许可/来源顺序。
- 主记录的 `explain_zh`、`why_zh` 若缺失，可从同许可层的其他来源补，但补入内容必须标注来源；跨许可层不补解析。
- 保留优先级争议（例如两条都是自编、但答案不一致）一律打 `unverified`，进剔除/复核队列，不自动选答案。

## 4. 剔除清单（命中即不进目标库，或只进指定池）

| 剔除/隔离项 | 处理 |
|---|---|
| `passage_missing`（原文缺图、原文残缺，例如新东方 1000 题中的 30 题） | 不进训练库、不进模考库；可留 C 层内部“待补原文”清单，不对外展示 |
| `unverified`（答案存疑、解析未复核、6 题原文残缺标 unverified 等） | 不进训练库；进复核队列，复核通过后去掉标志再进库 |
| 旧制 `deprecated`（旧制题型、改错题、旧制题号题数结构） | 不进图谱、不进训练库、不进模考库；仅在旧制对照文档中留名，不混入新制题库 |
| 模考整套题不进训练池 | 整套（题数达到模考下限，例如 toeic-reading 的 `FULL_MIN` 思路：题数 ≥90 的 form）一旦划入模考池，即打 `mock_only`；训练选题、薄弱点攻克、复习一律排除该套；同一套在训练中已出现过的题，做“已练过最少”优先选择时仍要排除，不得靠“练过最少”把模考题漏进训练 |
| 答案分布异常、选项缺失、四选项不全 | 不进库，进审题复核队列 |
| 超纲词未处理、节点粗打未复核 | 可进“待加工”队列，不进正式训练库；加工后复核再进 |
| 许可冲突未裁决（`license_conflict`） | 按最严层暂存，不进 A/B 层，直到人工裁决 |

剔除不是删除：被剔除的题保留原始记录 + 剔除原因 + 报告编号，便于以后补原文、复核后重新入选。

## 5. 用 DeepSeek 4.1 批量跑的苦力活清单

说明：以下任务均使用已授权的临时 DeepSeek 4.1 Key 临时调用，不把 Key 写入文件、日志或输出；窗口过期后停止并重新申请授权，不硬扛。模型输出一律视为“建议稿”，不是定稿。

### 5.1 去重报告（报告-only，不直接写库）

- 输入：归一化后的题目比对键、候选组、来源与许可层。
- 输出：精确去重映射表 + 近似去重候选报告（含相似信号、建议保留项、裁决栏）。
- 写库规则：报告-only。映射表经人工抽查（建议每批至少抽查 5%–10%，重点抽跨层组和答案不一致组）后，才可执行合并写库。
- 适用层：A/B/C 均可做比对报告；跨层报告不改变任何题目的许可层。

### 5.2 难度重评（建议稿，复核后可写库）

- 输入：题干、选项、节点、原文摘要（C 层原文只在私有环境内使用，不输出到公开文件）。
- 输出：每题 `difficulty_est` / score / band、难度理由（简短）、置信度（高/中/低）。
- 写库规则：低置信度一律不直接写库，进复核队列；高/中置信度经抽查后可写入 `difficulty_est` 字段，原始难度值保留在历史字段中，不覆盖丢失。
- 适用层：A/B 可写库；C 层只做内部校准（用于内部难度分布、选题测试），不生成可公开的难度报告。

### 5.3 解析补全（分层写库，C 层禁公开解析）

- 输入：题干、正确答案、节点、已有解析（若有）。
- 输出：中文解析 `explain_zh` 草稿 + 逐干扰项错因 `why_zh` 草稿。
- 写库规则：
  - A 层：草稿经审题（答案、逻辑、超纲词）后可写入库。
  - B 层：草稿经审题后可写入登录可见层，不进公开构建。
  - C 层：只做内部校准，不生成、不改写、不外发可公开解析。C 层题目若已有内部解析，仅用于内部难度/选题测试，不把模型生成的解析写成“可公开解析”或混入 A/B 层。
- 禁止：模型不得凭空补原文、不得改答案、不得把无许可原文改写后冒充原创题。

### 5.4 审题 item_audit（报告-only，复核后触发写库动作）

沿用 toeic-reading 的 `work/item_audit.py` 思路，批量跑以下检查，输出审题报告，不直接改题：

- 超纲词检查（NGSL / TSL 词表，专有名词、数字除外）
- 四选项完整性、答案唯一性、答案分布
- 干扰项错因完整性（pilot 题才有完整错因，其他题缺失要打标）
- 与已有库的近似重复
- P6/P7 bundle 与新制题号、题数、篇幅是否匹配
- 节点是否存在、是否粗打、是否与题型冲突

写库规则：报告-only。审题报告只触发三类动作：打 `flags`、进复核队列、或经人工确认后执行已定义的修正（例如补节点、补难度、剔除）。模型不直接在审题环节改答案或改原文。

### 5.5 批量任务总表

| 苦力活 | 输出物 | 报告-only 还是可写库 | C 层限制 |
|---|---|---|---|
| 去重报告 | 精确映射表、近似候选报告 | 报告-only；抽查后执行合并 | 可比对，不改许可 |
| 难度重评 | 难度建议稿 + 置信度 | 复核后可写 `difficulty_est` | 只内部校准 |
| 解析补全 | `explain_zh` / `why_zh` 草稿 | 审题后 A/B 可写库 | 不生成可公开解析 |
| 审题 item_audit | 审题报告 + flags 建议 | 报告-only；人工确认后触发修正 | 只内部报告，不公开示例 |

## 6. 可执行清单（按顺序做，不跳步）

### Phase 0：冻结与映射（不改库）

- [ ] 冻结统一 schema（第 1 节），写成 JSON Schema 或 Python dataclass，先跑通 A 层 pilot 107 题的映射。
- [ ] 建立来源清单：每个来源一行，含来源名、许可层、原始 commit/tag、题数、bundle 数。
- [ ] 建立三层目录隔离：公开构建输入、登录可见输入、私有输入分开存放，构建脚本按层取数。

### Phase 1：去重报告

- [ ] 跑归一化 + 精确去重，产出精确映射表。
- [ ] 跑近似召回，产出候选报告，人工裁决第一批（建议先裁决 P5，再裁决 P6/P7）。
- [ ] 输出第一份去重报告：distinct 题数（分层、分 Part）、重复组数、跨层重复数、待裁决组数。

### Phase 2：剔除与分池

- [ ] 按第 4 节打 flags，执行剔除与隔离。
- [ ] 划模考池：列出可用整套（题数、来源、许可层），打 `mock_only`，训练池排除验证跑一遍。
- [ ] 输出分池报告：训练池题数、模考池套数、复核队列题数、待补原文题数。

### Phase 3：DeepSeek 4.1 批量活（在授权窗口内优先跑）

- [ ] 先跑去重报告的模型辅助裁决建议（不直接裁决）。
- [ ] 再跑难度重评：A 层优先，B 层次之，C 层仅内部校准。
- [ ] 再跑解析补全：先补 A 层 `explain_missing` / `why_missing`，再补 B 层；C 层不产出公开解析。
- [ ] 每批跑完都跑 item_audit，出审题报告，抽查通过才写库。

### Phase 4：写库与泄漏检查

- [ ] 写库动作一律走“报告 → 抽查 → 写库 → 复查”四步，写库日志保留批次号、模型、抽查比例。
- [ ] 跑公开构建泄漏检查：B/C 层文字不在公开产物中；失败则停发。
- [ ] 跑训练/模考分池回归检查：模考套题不在训练选题结果中出现。

### Phase 5：交付物

## 7. 停止条件（出现任一即停，不硬跑）

- 授权的临时 Key 窗口过期、配额变化、或返回持续 401/403/5xx：停止批量任务，记录断点，不重试同一批原样请求。
- 泄漏检查失败：停止发布，定位漏入的 B/C 层内容。
- 去重裁决中出现答案不一致且无法复核：该组保持 `unverified`，不写库。
- 任何一步要求把 C 层题目或解析写进公开文件：拒绝该步，改走内部版流程。

## 8. 与其他 Track 的接口（不越界）

- UX Track：本 Track 只交付题库字段、难度、解析、flags；不决定界面文案、Tab 结构、答题器交互。
- 算法 Track：本 Track 交付 `difficulty_est`、`target_time_sec`、`node_ids`；Elo、FSRS、预测分、选题权重由算法 Track 定，本 Track 不改算法公式。
- 架构 Track：本 Track 不建仓库、不定部署方案；分层文件路径、构建输入、泄漏检查脚本位置由架构 Track 定，本 Track 只给输入规范。
