# toeic-next 最终方案（完整体验版，2026-11-03 修订）

本文件是把此前所有已确认决定、三路方案、Hark 补正和四路交叉审视（已剔除 kimi-k2.6）整合后的一份可执行方案。2026-11-03 15:07 用户明确纠正：不按 MVP 考虑，按完整体验安排任务，避免历史上老是做一半的问题。因此本版删除“前两周最小可行版截断”的框架，改为完整范围、分模块验收：功能可以按依赖分阶段做，但每个模块必须做到可交付、可测试、可上线，不留“只写了方案、没落地”的半成品。凡评审共识与 Hark 证据冲突的地方，按“用户实测反馈优先于评审通用意见”处理，并在文中注明。

## 0. 一句话

为 35–40 岁、工作多年、四六级多年未考、忙、有家庭、精力有限、不擅背单词和语法的用户（另有 50 岁以上内部成员），做一个只练 TOEIC 阅读、用最少精力涨分的工具。核心指标只有两个：每投入 1 分钟涨多少分，以及明天还愿不愿意回来。

## 1. 已确认的硬性决定

- 仓库：toeic-next（公开）+ toeic-next-private（私有），与历史分离，已建仓并推入初始 README。
- 品牌：Rescheduled Inc.
- 部署：Cloudflare Pages + Supabase，多设备用。前端单文件离线构建 + PWA，本地先行、联网再同步，同步失败不丢本地进度，进度码导入导出兜底，账号页才要求登录。
- 只练阅读：Part 5（30 题）/ Part 6（16 题）/ Part 7（54 题），现行题型，75 分钟 / 100 题。旧制一律标 deprecated，不进训练池。
- 许可三层绝不混：A 可公开（自编、MIT、NGSL/TSL、原创技巧）；B 登录可见（Supabase gated_content + 构建时泄漏检查）；C 仅自用（ETS 转录、新东方等无许可题，私有仓 + 私有 Release，只做内部校准，绝不生成可公开解析）。

## 2. 产品形态：IM 模拟工作台 + 今日提分主流程

- 外壳是公司 App（工作台 / 收件箱 / 手册 / 复习 / 绩效），沉浸靠外壳和单主按钮实现，不靠藏数字。
- 首页（2026-11-03 用户确认的合并方案）：首页是 IM 模拟工作台，不是只有一个按钮。工作台顶部是身份、目标分和差距、考试倒计时，底栏是工作台 / 收件箱 / 手册 / 复习 / 绩效；工作台里唯一主按钮是“开始今天的工作”，即今日提分流，固定走 P5 8 题 → P6 1 篇 → 最多 5 分钟错题复习。下面队列就是该流程的顺序（Ken 审稿为 P6、客户邮件为 P7、Dana 退回为复习跟进），点主按钮按顺序走，点队列某条直接跳进对应一步，状态互通。其他入口不是删除，而是按渐进披露先收起、全功能一直在。
- 任何时刻一个主按钮。压力只来自时间，不羞辱、不惩罚漏做、不设连续打卡惩罚。
- 字号可调，不默认放大；手机 / 平板 / PC 分开布局，PC 1280 为基准，P7 长文左文右题，手机原文 / 题目切换。

## 3. 反馈规则：Hark 方向优先，预测分收紧

- 默认 3 秒回报闭环（Hark UX v2，opus-5.5 讨论 + 用户实测反馈）：答后立刻给对错、用时、掌握度变化。藏数字的版本用户已明确投诉过没有计时、没有对错、没有沉浸感，因此不采纳评审“完全隐藏掌握度”的建议。
- 预测分是唯一收紧项：不给虚假精确的单点分，满 100 道已核验题后才以区间显示，区间带刻度和说明。
- 计时语义写清：训练中是“本题用时”，不是倒计时；整套剩余时间只在模考中出现。
- 规则卡只在连错时出现：同主节点连错 ≥2 次、训练 / 攻克 / 复习模式下，答后出现一个“看规则卡”按钮，不自动弹全屏；卡片结构固定为标题即结论、一句话做法、一个示例、适用题型、练 5 题入口。

## 4. 引擎与选题：先简单，后校准

- 冷启动不做 12–13 题无反馈诊断驱动全图谱。那是三路评审共同反对的点：样本太小、方差巨大、首体验只被考不被教会。
- 冷启动方案：按考频排序起步，前 3 次正常练习当隐式诊断；入职时可做一个可选的 10 道 P5 快测，答完立刻给反馈，不作为 gate。
- 第一阶段（前两周）：选题只用“考频 × 错误次数”的简单排序，不上 Elo + FSRS 全套；复习用轻量错题重排。等有真实答题数据后，第二阶段再上 Elo 掌握度、FSRS 间隔和预测分区间校准。
- 选题优先级（评审 3/3 一致）：P5 > P6 > 复习 > P7 > 手册。P7 虽然占 54 题，但对阅读速度慢的用户单位时间收益最低，前两周不练 P7。
- 模考：前两周不做 75 分钟整套；之后也先拆段或每周最多 1 次，不默认推送。模考题交卷后记 used、不再进训练池，但刚错的题在复习中仍可重现（不把“用过即删”做成复习断点）。

## 5. 会话与复习硬顶

- 主会话：5 分钟快闪为默认入口，20 分钟和 75 分钟模考全部建好；20 分钟结构为 P5 + 复习 + P6，75 分钟为完整模考链路，用户侧默认不推送，不等于功能不做。
- 复习硬顶（三路共识）：每会话 ≤4 道，且不超过会话时间的 30%；每天复习债 ≤5 分钟；复习只做 P5 / P6 同主节点错题，且放在新学完成后出现。
- 当日只做一次正式结算，不做每 5 分钟一次的成绩屏；未完成当日任务时只显示“继续”，不清零。

## 6. 题库与手册：完整建好，前台渐进披露

- 完整范围：305 节点、82 技巧、12 章手册、P5 / P6 / P7 已核验题池全部建好并通读修正。前台渐进披露：默认先按高频排序展示 20–30 个节点、10–15 条技巧，其余全库可查、可搜，不删、不留半成品。
- 第一批工作顺序（已确认）：先清洗 / 解决错题，再顺道做难度、必要程度、答题技巧划分，同一趟完成，低置信度不写库。
- 上线门槛（评审共识）：63 道答案键争议必须在训练前隔离出训练池，标 unverified 的题不自动选答案、不进诊断和早期题池；去重先出报告再写库，精确哈希 + 近似候选人工裁决，保留来源链；剔除 passage_missing、unverified、旧制 deprecated，模考整套不进训练池。

## 7b. 防“做一半”机制

- 每个模块必须同时有：方案、实现、真机测试、数据 / 内容、文档，缺一项不算完成。
- 每个模块有验收标准，不以“写了文档”或“跑通一次演示”当完成。
- 并行三路（UX / 题库 / 算法）每完成一个模块就做一次集成检查：题库输出统一 JSON、引擎只读统一 JSON、UX 只读引擎状态与规则卡事件，接口变了三路同步改。
- 旧仓库只读归档后不再回头改旧项目，所有新工作只进 toeic-next / toeic-next-private，避免双线半成品。

## 8. 验证与叫停（14 天初判，28 天复判）

- 留存：次日回访 ≥40%、D7 ≥30% 为通过；D7 <15% 或中位会话数 <4 为叫停信号。
- 提分：固定 30 题锚题（P5 / P6 高频）第 0 天 vs 第 14 天对照，正确率 +8 个百分点，或用时降 15% 且正确率不降；每分钟进步低于 0.04 个百分点为叫停信号。
- 会话健康：5 分钟会话完成率 ≥85%；复习占比 ≤30%，超标即砍复习配额。
- 不以预测分当成效。样本小时用每人自身前后对照，不拼大样本统计。

## 10. 本方案与旧三路方案的不同点（对照表，非新增承诺）

- 首页：旧方案 5 个 Tab 平铺 → 本方案前两周单一“今日提分”流。
- 诊断：旧方案 12–13 题无反馈 → 本方案隐式诊断 + 可选 10 道 P5 有反馈快测。
- 引擎：旧方案一开始就 Elo + FSRS → 本方案先简单排序，数据够了再上复杂引擎。
- 预测分：旧方案默认显示单点变化 → 本方案掌握度变化照常给，预测分满 100 道已核验题后只给区间。
- 手册 / 图谱：旧方案 12 章 + 305 节点全量 → 本方案前两周只开高频子集，其余按需出现。
- 模考：旧方案 75 分钟为常规活动 → 本方案完整建好 75 分钟模考，默认不推送、拆段或每周最多 1 次，用户侧不被打扰，但功能不缺。
